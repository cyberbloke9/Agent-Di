# Security & QA audit — September 2026

Four independent agents reviewed the milestone-1 code: a security/pen-test pass,
an adversarial attack on the policy (money) engine, a commerce edge-case pass,
and a code-quality review. All ran against this repo only; nothing external was
touched. This records what they found and how it was resolved.

## Headline
- **No confirmed money-path break** in the current flow (55-case policy battery
  passed). The engine is the only component that can authorise money, no model
  runs inside it, payees come only from the registry, and the PIN never leaves
  the user's phone.
- The most important fix was that the provenance gate was **fail-open by
  default**; it is now fail-closed.

## Findings and resolutions

## Deferred (low, design-acceptable) — tracked, not yet fixed
- **Commerce #4:** a single generic token (e.g. "gold") matches any title containing
  it. Acceptable for now; the brand-strict path covers the important case. Revisit
  with the embedding matcher.
- **Commerce #6:** multipack titles like "6 x 200 ml" parse as "200 ml". Revisit the
  size parser when wiring a real catalogue.
- **Optimizer optimality:** the exact path is optimal; the bounded fallback (only for
  very large carts) may be non-optimal. Documented in the module.
- **Journal HMAC key management** and **third-party-data handling in ingestion** are
  design items for later milestones, not code bugs.

## Confirmed sound (no change needed)
Money arithmetic (bigint, non-negative), the spend-ledger window/floor math, the
ASCII-only VPA regex (no homoglyphs, no catastrophic backtracking), store text
treated strictly as data (never executed), and cross-store id-spoof rejection.
